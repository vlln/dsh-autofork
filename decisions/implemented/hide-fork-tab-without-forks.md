# 没有分叉时不显示「分叉」页签

分类：feature / ui

## Problem

「分叉」页签原来是**常驻注册**的：`conversation.view` 的 entry 在插件 apply 时就注册，此后一直在
tab 栏里。于是一条从未分叉、也不是谁的分叉的会话也会看到它——点进去只有自己一条，摘要只能写
`1 条会话 · 还没有分叉`。用户 2026-10 判定这是噪声："当 session 没有 fork 时，应该隐藏「分叉」页签。"

## Decision

- 页签按**本会话所在家族有没有分叉关系**显隐：客户端跟随轮询快照，`nodes.length > 1` 时注册
  `conversation.view` 的那一条 list 条目，否则注销它。判据只有一个（家族节点数），不引入第二套
  可见性状态。
- 官方 `ui-conversation` 自己订阅 `conversation.view` 的变更重算 tab 列表（`refreshViews`），所以
  注册/注销这一条条目就是"显示/隐藏页签"，**不碰任何官方 DOM**，也不需要 CSS 隐藏。
- 页签显隐只影响**入口**：家族关系、接管绑定、自动回注开关、取消授权与后台计数全部照旧，与
  "有没有显示这个页签"无关。
- 随之删掉空态那句 `还没有分叉`：页签只在有分叉时存在，这句话在页签里已不成立。

## Alternatives considered

- **CSS / DOM 隐藏**：要按官方 tab 栏结构改 DOM，属于自造缝，且会在宿主改结构后静默失效。
- **常驻页签 + 空态文案**：那正是被否掉的噪声本身。
- **当前会话一变就先隐藏、拿到数据再显示**：会话之间切换（两个都有家族）会让页签闪一下，
  比"最多晚一个轮询周期"更糟。按 id 缓存各会话的家族数据属于额外状态，收益不足以抵消复杂度。

## Consequences

- 切换会话后，页签最多晚**一个轮询周期（≤1s）**才收起：轮询是家族数据的唯一来源。页签内容本来
  就有同样的刷新粒度。
- `BranchView` 里 `nodes` 为空/只有一条的分支退化为防御性路径（切会话的那一帧可能短暂渲染），
  不再承担"空态"这一产品语义。
- 宿主 half、HTTP 契约、工具面与存储格式都未改动。

验证（隔离 DSH web 实例，真实浏览器 + CDP）：家族 3 节点的会话，tab 栏为
`Chat | Trajectory | 分叉` 且视图挂载；点开一条 1 节点的独立会话，tab 栏只剩 `Chat | Trajectory`，
视图元素消失，客户端轮询用的正是该会话 id（走的是 `nodes.length === 1` 这条判据，不是"没有当前
会话"）；切回家族会话页签再次出现。客户端诊断随之为 `view.shown → view.hidden → view.shown`。
